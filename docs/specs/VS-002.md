# VS-002 — CI Provider Abstraction

## IntentSpec

### Problem

The complete program cannot depend on a single CI provider. Hosted minutes, a disconnected self-hosted runner, provider outages or unavailable secrets must not silently convert required validations into PASS or stop development when an equivalent provider is available.

### Business objective

Provide a provider-neutral validation contract with reproducible evidence, explicit fallback and honest BLOCKED outcomes.

### Boundaries

- This slice defines CI provider governance and local evidence, not the complete .NET build pipeline.
- It does not store provider secrets in the repository.
- It does not automatically downgrade required checks.
- A missing or non-equivalent validation remains BLOCKED.

## BehaviorSpec

### Provider types

1. GitHub Actions hosted.
2. GitHub Actions self-hosted.
3. CircleCI.
4. Local Evidence Provider.

### Selection flow

```text
validation request
→ load provider catalog
→ filter enabled and capable providers
→ check required evidence level
→ select highest-priority available provider
→ execute
→ normalize evidence
→ PASS / FAIL / BLOCKED
```

### Required evidence envelope

- provider ID and type;
- validation contract ID;
- command or workflow identity;
- source commit SHA;
- start/end timestamps;
- exit code and result;
- stdout/stderr artifact references;
- hashes;
- environment summary;
- signature or provenance field;
- equivalence declaration;
- retry/fallback chain.

### Rules

- `SKIPPED` is never equivalent to `PASS`.
- Local evidence can satisfy a gate only when the contract explicitly allows it.
- A fallback must run the same validation contract or an approved equivalent.
- Provider availability is runtime state, not hard-coded truth.
- Secrets are referenced by environment-variable name only.
- Commands are invoked without shell interpolation.

### Errors

- unknown provider;
- duplicate provider ID;
- no capable provider;
- invalid evidence;
- source SHA mismatch;
- timeout;
- missing secret;
- non-equivalent fallback.

## TDD Dual

### RED-I

Tests must fail because the following do not yet exist:

- `config/ci/providers.json`;
- `schemas/ci-evidence.schema.json`;
- `scripts/validate_ci_providers.py`;
- unique priorities and provider IDs;
- at least one hosted, self-hosted, CircleCI and local provider.

### RED-E

The repository cannot yet produce a normalized local evidence file for a governance validation or explain why fallback is blocked.

### GREEN-I

- provider catalog validates;
- evidence schema validates representative PASS, FAIL and BLOCKED envelopes;
- provider selection is deterministic;
- duplicate IDs and unsupported types fail.

### GREEN-E

A local evidence command executes `verify_plan_integrity.py`, writes a normalized evidence JSON and returns the original exit code without claiming provider equivalence beyond the configured contract.
