# VS-111 — EPUB renderer

## Intent

Render a deterministic, standards-oriented EPUB package from one exact approved VS-110 canonical manuscript revision without mutating upstream authority.

## Behaviors

1. A render request identifies workspace, project, manuscript assembly, exact revision, canonical content digest, manifest digest, locale, EPUB profile, actor and deterministic request fingerprint.
2. The renderer requires the current approved VS-110 manuscript authority and rejects stale, missing, cross-workspace, digest-mismatched or non-approved input.
3. Front matter, body and back matter are converted into explicit ordered XHTML documents with stable identifiers and deterministic filenames.
4. Navigation, package metadata, spine, manifest, landmarks, language, title, authorship, identifiers and modified timestamp are generated from governed inputs.
5. Citations, notes, tables, figures, captions and accessibility alternatives preserve exact source lineage and semantic relationships.
6. Binary and visual resources must be present, rights-approved, content-addressed and referenced exactly once.
7. EPUB ZIP ordering, compression policy, timestamps, media types and entry paths are deterministic; `mimetype` is first and uncompressed.
8. Validation records structural, navigation, metadata, resource, accessibility and EPUBCheck-compatible findings; blocking findings prevent approval.
9. Exact replay is idempotent; conflicting request reuse and stale revisions fail without duplicate outputs or events.
10. Requests, attempts, package entries, validation findings, decisions, receipts, append-only history and Outbox messages are committed atomically and reconstructed from SQLite after restart.
11. Approval freezes an immutable EPUB artifact digest for VS-112 and later production slices; changes require a superseding render revision.

## Invariants

- No approved EPUB references stale or mismatched VS-110 authority.
- Package structure and bytes are deterministic for identical governed inputs.
- Upstream manuscript authority is read-only.
- Every packaged resource has exact lineage, media type and digest.
- Exact replay cannot duplicate durable work or Outbox effects.
- Failed validation or transaction cannot expose an approved partial package.

## Gates

- Typed render request, authority, package, entry, finding, decision and state contracts.
- Exact VS-110 authority enforcement.
- Deterministic XHTML, navigation, OPF and ZIP assembly.
- EPUBCheck-compatible and accessibility validation evidence.
- Approval, repair, rejection and supersession governance.
- Replay, optimistic concurrency, rollback, restart recovery and workspace isolation.
- Append-only history and deterministic exactly-once Outbox.
- Dual TDD GREEN, Auditoría M, Meta-Audit, RetroSpec and complete same-head CI.
