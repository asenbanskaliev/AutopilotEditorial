# VS-002 — RetroSpec

## Implemented behavior

- `config/ci/providers.json` defines four provider types and five validation contracts.
- Provider selection is governed by enabled state, capability, unique priority and runtime availability.
- `scripts/validate_ci_providers.py` validates the catalog and evidence-result contract.
- `schemas/ci-evidence.schema.json` defines normalized PASS, FAIL and BLOCKED evidence.
- `scripts/run_local_validation.py` executes an approved local equivalent without shell interpolation and writes hashed evidence.
- Governance GitHub Actions validates the catalog, executes tests, generates local evidence and uploads it as an artifact.
- `.circleci/config.yml` provides an equivalent governance pipeline when CircleCI is configured.
- `.NET CI` remains assigned to a self-hosted runner and is not part of this governance fallback.

## Contracts

- Provider catalog: `config/ci/providers.json`.
- Evidence schema: `schemas/ci-evidence.schema.json`.
- Provider validator: `scripts/validate_ci_providers.py`.
- Local evidence runner: `scripts/run_local_validation.py`.
- Operational policy: `docs/ci/PROVIDER_CONTRACT.md`.

## Approved decisions

- GitHub-hosted remains highest priority for lightweight checks.
- Self-hosted remains preferred for .NET, integration and rendering.
- CircleCI is defined but disabled until external project credentials are confirmed.
- Local evidence may satisfy only contracts with `localEquivalentAllowed=true`.
- `release.full-program` explicitly forbids local equivalence.
