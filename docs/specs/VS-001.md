# VS-001 — Backlog and GitHub Project

## IntentSpec

### Problema

El plan maestro existe en el repositorio, pero el desarrollo no puede continuar de forma fiable si las vertical slices no se convierten en trabajo operativo y reanudable desde GitHub.

### Objetivo

Crear un mecanismo reproducible que transforme `full-program-backlog.csv` en issues de GitHub y permita seleccionar la siguiente slice READY sin depender del historial del chat.

### Límites

- No implementar todavía código productivo del MCP.
- No crear un issue por función interna.
- No cambiar el alcance de las 104 slices.
- No considerar el GitHub Project visual como fuente canónica; el CSV y los issues son la fuente trazable.

## BehaviorSpec

### Flujo principal

1. Leer `docs/master-plan/full-program-backlog.csv`.
2. Validar IDs, orden, estados y dependencias.
3. Crear labels de gobierno si no existen.
4. Crear issues para las slices de la wave activa.
5. Vincular cada issue con fase, objetivo, dependencia y gates.
6. Resolver la siguiente slice READY.
7. Actualizar `EXECUTION_STATUS.md`.

### Estrategia de waves

- Wave 0: VS-000 a VS-002.
- Wave 1: Foundation, VS-010 a VS-016.
- Wave 2: MCP, VS-020 a VS-028.
- Wave 3: OpenCode y Autopilot, VS-030 a VS-047.
- Wave 4: Authoring y Coherence, VS-050 a VS-070.
- Wave 5: Professional, Research y Rights, VS-080 a VS-095.
- Wave 6: Visual y Production, VS-100 a VS-118.
- Wave 7: Operations y Enterprise, VS-120 a VS-137.
- Wave 8: Certification, VS-140 a VS-148.

Los issues de una wave pueden crearse anticipadamente, pero una slice solo pasa a READY cuando sus dependencias están verificadas.

### Errores

- ID duplicado.
- Dependencia inexistente.
- Estado no permitido.
- Issue duplicado.
- GitHub no disponible.
- Falta de permisos.

## TDD Dual

### RED-I

El test debe fallar si:

- hay IDs duplicados;
- una dependencia no existe;
- el orden no es creciente;
- el backlog no contiene 104 slices;
- la primera slice READY no es VS-000 en el estado inicial.

### RED-E

Antes de esta slice no existía ningún issue operativo para el backlog. La evidencia inicial es el issue #2 creado para VS-001 y la ausencia de issues para las siguientes waves.

### GREEN-I

Los validadores y tests de gobierno pasan sobre el CSV canónico.

### GREEN-E

- existe issue para VS-001;
- existe estrategia de waves ejecutable;
- `seed_issues.py` puede crear issues reproduciblemente;
- la siguiente slice se puede resolver desde el repositorio.

## Auditoría M

- M1: comprobar que el issue y la spec coinciden.
- M2: revisar scripts y ausencia de efectos laterales no autorizados.
- M3: revisar que los tests detectan defectos reales.
- M4: revisar permisos y uso seguro de `gh`.
- M5: verificar que una nueva sesión puede seleccionar la siguiente slice.

## Definition of Done

- DUAL_RED_CONFIRMED.
