# VS-001 — RetroSpec

## Implemented behavior

- The immutable 104-slice plan remains in `docs/master-plan/full-program-backlog.csv`.
- Mutable execution state is stored in `docs/execution/SLICE_STATUS.csv`.
- `docs/execution/WAVE_PLAN.md` groups every phase into controlled waves.
- `scripts/verify_completion.py` computes effective status using the overlay.
- `scripts/next_slice.py` resolves READY work using dependency completion.
- `scripts/seed_issues.py` can create labels and issues reproducibly through GitHub CLI.
- Governance CI executes plan validation, completion validation and unit tests.

## Contracts

- Plan contract: `full-program-backlog.csv`.
- Execution contract: `SLICE_STATUS.csv`.
- Wave contract: `WAVE_PLAN.md`.
- Completion contract: `COMPLETION_CONTRACT.md`.
- Re-entry contract: `RESUME_PROTOCOL.md`.

## Approved deviations

The initial seed used a JSON-oriented script design. VS-001 standardizes the active repository on CSV because:

- it is easier to review in pull requests;
- it supports small status diffs;
- it avoids rewriting a large JSON file for each transition.

No scope was removed.
