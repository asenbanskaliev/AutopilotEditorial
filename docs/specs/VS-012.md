# VS-012 — SQLite Persistence

## IntentSpec

### Problem

BookStudio needs durable local state before project, artifact, Outbox and workflow schemas are implemented. A naive shared SQLite connection or uncoordinated writes would create lock contention, partial migrations and unsafe backups.

### Objective

Provide a minimal, provider-specific SQLite foundation with explicit lifecycle, migration, serialized writing, integrity and backup contracts while keeping editorial entities outside this slice.

### Technology decision

- `Microsoft.Data.Sqlite` version `10.0.10`.
- Direct ADO.NET provider usage; no EF Core.
- SQL migrations embedded in `BookStudio.Infrastructure`.
- WAL journal mode.
- Foreign keys enabled on every connection.
- Busy/default timeout of five seconds.
- One application write queue per workspace database.
- Online backup through `SqliteConnection.BackupDatabase`.

## BehaviorSpec

### Application port

`IWorkspaceDatabaseLifecycle` exposes:

- initialize;
- health/integrity status;
- online backup.

It does not expose `SqliteConnection`, SQL or provider types.

### Infrastructure components

- `SqliteWorkspaceOptions` validates and canonicalizes paths.
- `SqliteConnectionFactory` creates configured connections.
- `SqliteMigration` describes version, name, SQL and SHA-256.
- `SqliteMigrationCatalog` loads embedded migrations in deterministic order.
- `SqliteMigrationRunner` creates the migration ledger and applies pending migrations atomically.
- `SqliteWriteQueue` serializes write transactions through a bounded channel.
- `SqliteWorkspaceDatabase` composes initialization, metadata access, integrity, checkpoint and backup.

### Initial schema

Only generic infrastructure tables:

- `schema_migrations`;
- `workspace_metadata`.

No project, chapter, artifact, Outbox or job table is introduced in this slice.

### Connection contract

Every opened connection must enforce:

- foreign keys ON;
- busy timeout 5000 ms;
- WAL after initialization;
- synchronous NORMAL;
- pooling enabled;
- read/write/create mode;
- shared cache.

### Migration contract

- versions are positive and unique;
- migrations ordered by version;
- SQL and SHA-256 embedded;
- a migration and its ledger insert commit in the same transaction;
- an already applied migration with a different hash is a blocking error;
- repeated initialization is idempotent.

### Write queue contract

- bounded capacity;
- FIFO single consumer;
- one transaction per operation;
- commit only on success;
- rollback on exception or cancellation;
- operation completion propagated to caller;
- graceful drain on disposal;
- no work accepted after completion.

### Backup contract

- serialized behind the write queue;
- checkpoint before backup;
- destination parent created;
- destination must differ from source;
- partial destination removed on failure;
- backup opened and `quick_check` verified by integration tests.

### Health contract

Returns:

- database exists;
- journal mode;
- foreign-key status;
- migration count/latest version;
- `quick_check` result;
- database file length.

### Errors

- invalid or escaping path;
- duplicate migration version;
- changed applied migration hash;
- migration SQL failure;
- write queue closed;
- write timeout/SQLite busy;
- integrity failure;
- backup destination equals source;
- backup verification failure.
