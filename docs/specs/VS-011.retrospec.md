# VS-011 — RetroSpec

## Implemented behavior

- `docs/architecture/architecture-policy.json` is the canonical versioned architecture contract.
- The policy defines project membership, layer, csproj path, Release assembly path, allowed project references, allowed BookStudio assembly references, package policy, scoped AGENTS path and forbidden namespace prefixes.
- `ADR-001` records the dependency direction and ownership rules.
- Every project has scoped instructions with Allowed and Forbidden sections.
- Python governance tests read the policy and validate solution membership, project references, package policy, namespace imports and instructions.
- The .NET architecture executable reads the same policy, validates project XML and inspects compiled PE metadata without executing product code.
- Compiled BookStudio assembly references must be a subset of the allowed policy references.

## Contracts

- Architecture policy: `docs/architecture/architecture-policy.json`.
- Decision: `docs/architecture/ADR-001-clean-architecture-boundaries.md`.
- Static enforcement: `tests/governance/test_architecture_policy.py` and `test_solution_baseline.py`.
- Compiled enforcement: `tests/BookStudio.Tests.Architecture/Program.cs`.
- Contributor guidance: project-scoped `AGENTS.md` files.

## Residual risks

- The namespace scan currently validates `using` directives; fully qualified forbidden type usage will require semantic analysis when Roslyn analyzers are introduced.
- Compiled reference validation only governs assemblies beginning with `BookStudio.`; package and framework governance are handled separately.
- Adding or renaming a project requires an intentional policy update and ADR impact review.
