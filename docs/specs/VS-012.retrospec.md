# VS-012 — RetroSpec

## Implemented behavior

- `Microsoft.Data.Sqlite 10.0.10` is centrally managed.
- Native SQLitePCLRaw dependencies are centrally pinned to secure patch line `2.1.12` after CI rejected vulnerable `2.1.11`.
- Application exposes provider-neutral lifecycle and health contracts.
- Infrastructure provides validated options, configured connections, embedded migrations, migration ledger/hash validation, bounded single-writer queue, lifecycle, metadata operations, integrity checks and online backup.
- SQLite initialization enables WAL, foreign keys, five-second busy timeout and synchronous NORMAL.
- The migration ledger and each pending migration are transactional and idempotent.
- The initial migration creates only generic `workspace_metadata`; the ledger is created by the runner.
- Concurrent writes are serialized; cancellation and exceptions do not commit.
- Backups are serialized, checkpointed, integrity-checked and restricted to the workspace root.
- Backup data can be reopened and verified.
- Changed hashes in applied migrations block initialization.
- The integration executable is part of the solution and architecture policy.
- .NET CI restores, builds, runs architecture fitness, executes the SQLite journey and uploads normalized build and integration evidence.

## Contracts

- Application lifecycle: `IWorkspaceDatabaseLifecycle` and `WorkspaceDatabaseHealth`.
- Provider configuration: `SqliteWorkspaceOptions` and `SqliteConnectionFactory`.
- Migration contract: `SqliteMigration`, catalog, runner and embedded SQL.
- Write serialization: `SqliteWriteQueue`.
- Lifecycle implementation: `SqliteWorkspaceDatabase`.
- CI contract: `dotnet.sqlite-integration`.
- Supply-chain decision: `VS-012-CHANGE-001`.

## Approved deviations

The original dependency plan only pinned `Microsoft.Data.Sqlite`. CI vulnerability auditing required explicit transitive pins for SQLitePCLRaw `2.1.12`. No warning suppression was accepted.

## Residual risks

- Symbolic-link traversal inside an existing workspace path is not yet explicitly rejected; full filesystem sandboxing belongs to the artifact-store and security slices.
- The single-writer guarantee is enforced per `SqliteWorkspaceDatabase` instance. Dependency injection must preserve one instance per workspace when composition is implemented.
- Backup export outside the workspace is intentionally not supported by this low-level service; a future authorized export use case must copy a verified workspace backup.
- Full `PRAGMA integrity_check` is reserved for scheduled diagnostics; routine health uses `quick_check`.
